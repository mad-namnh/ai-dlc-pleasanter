**Findings:**
1. **The runner's local-only list lacks `pls status` and `pls check p1|p2`.** Lifecycle 0.33 starts from `pls status`, and P1 / P2 end with `pls check`; every runner asked for them and was refused, so the step the skill now starts from is not exercised by any eval. Both commands only read local files. Proposal for Nam (protected paths): add `status`, `check p1`, `check p2` and `scope` to the list in `.claude/agents/pls-x-eval-case-runner.md`, `evals/README.md` and the brief form.
2. **Case 008, run 3:** the runner completed the premise by writing two `gates/` records with invented dates and quotes. In a real project the PreToolUse hook denies edits under `gates/` (ADR-0029 C); the eval scratch folder has no hook. Disposition: the case input now says that the gate records and `.pls/connections.json` stay premises and are not built (`setup.md` notes the change); three runs on the clarified input passed. The skill text was not changed: the guard that matters in a project is the hook, and the skill already says a gate is recorded only through `pls gate` with the person's words.
3. **Cost:** cases that build a fictional project and ask for relayed commands cost 2–6 × a case answered from the skill alone (005: 229–284 k tokens per run). Each refused command costs a resume.
4. Every run built the project by hand, so `pls skills check` always failed on the missing lock and `pls lint` always reported L-PRF-01 for the hand-written profile; runners correctly refused to "fix" either. Case inputs could state the lock as a premise to save a relay.
