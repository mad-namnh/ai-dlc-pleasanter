## Findings for the framework

1. **Both runs found an interaction slice #1 missed:** once the 未完了 view includes the escalated status, notification #1 (to [Manager], condition = view 2, watches Status) also fires on every escalation → the manager gets a second, misleading 「…未対応です」 mail. This applies to release R-20261105-01 on stg. Both runs also flagged the 対応期限 reminder (condition = view 2) and that notification #1 does not actually filter on 優先度. → added to the rubric (I9).
2. **Interpretation variance:** two runs with almost the same skill made opposite assumptions about the status. One run per case is not enough to judge a skill; run each case ≥ 3 times once grading is automated.
3. The rubric's item on escalated state assumed the slice #1 interpretation; reworded to be interpretation-neutral.
