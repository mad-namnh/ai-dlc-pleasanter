- **Plan item:** Step 4c BR3 (ADR-0001 round 2, ADR-0012 probe)
- **Environment:** MADLAB dev, Pleasanter 1.5.2 (build token `201520`, schema `1.017`), folder AI-DLC-DEMO (44708)
- **Probe sites (left in place, a person deletes them):** `zz_probe_br3_results` 44734 (Results), `zz_probe_br3_dash` 44735 (Dashboards)
- **Script:** `spike/round-trip/scripts/br3_probe.py` (writes only through `pls_http.assert_writable`)

## Why

The first brownfield candidate keeps the custom layout of its main screen in `Htmls` / `Scripts` / `Styles`, and uses dashboards and scheduled server scripts. Spike round 1 never tried these (checklist rows 16–18 ➖). `updatesite` replaces the whole configuration (D4), so a component that does not round-trip can be lost by any deploy.

## Results

| Check | Results site (Htmls, Scripts, Styles) | Dashboard (parts 1, 3, 4) |
|---|---|---|
| 1. sent vs stored | stored unchanged (Japanese text, CRLF, template literals, `<script>` inside an HTML block, `Disabled`) | defaults added on save: `CalendarShowStatus`, `DisableAsynchronousLoading`, `KambanAggregationView`, `KambanShowStatus`, `TimeLineItemCount`, `SiteId` on the HTML part; `View` filled with defaults (D8-like) |
| 2. raw round trip | 0 differences | 0 differences |
| 3. pls round trip (unpack → files → pack → updatesite → export) | 0 differences; files `htmls/`, `scripts/`, `styles/` + `_index.json` | 0 differences |
| 4. references | the dashboard id inside a script body became `${site:probe_b}`; a payload for another environment carries that environment's id | site ids in `SiteId`, `TimeLineSites`, `CalendarSites`, `CalendarSitesData`, `HtmlContent` became `${site:probe_a}` and resolve per environment |

**Failure found:** a timeline (1) or calendar (4) part **without `View`** makes `updatesite` fail with **HTTP 500** and an HTML error page; the HTML part (3) does not need it. With `"View": {}` all three save. Real exports always carry `View` on types 1, 4 and 5.

Not tried: part types 0 (quick access, `QuickAccessSites` JSON text) and 5 (kanban); status control (`StatusControls`); formulas. `pls release-plan` now refuses them until probed (`tools/pls/pls_scope.py`).

## Scheduled (background) server scripts — ADR-0012

| Question | Answer |
|---|---|
| Where configured | Tenant management screen → tab サーバスクリプト (official manual, managers-guide / tenant-administration / background-server-script) |
| Settings | ID, 実行ユーザ, タイトル, 名称, サーバスクリプト, 無効, 共有, one or more スケジュール (毎時 in 5-minute steps / 毎日 / 毎週 / 毎月 / 1回だけ, タイムゾーン) |
| Prerequisite | `BackgroundServerScript` in `Script.json`; from 1.5.7.0 execution per environment (`EnvironmentVariables` in `BackgroundService.json`, `DeploymentEnvironment` in `Service.json`) |
| API | None documented. Read-only probe with the admin key: `/api/tenants/get`, `/api/tenants/1/get`, `/api/tenants/gettenant`, `/api/items/1/gettenant` → HTTP 404 |
| Timeout | not stated in the manual; not probed |

→ ADR-0012 option **B** (files in git, manual deploy, verification by a person).
